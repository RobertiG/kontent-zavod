# CLAUDE.md — правила проекта «Контент завод»

Студия контента для продавцов маркетплейсов: видео, карусели, интерьерные фото, RICH и SEO карточек. Главный документ — бизнес-план v18 (Google Диск → «Документы»). Этот файл Claude Code читает сам в начале каждой сессии; люди читают его же.

## Кто и как
- Кристина — руководитель проекта: клиенты, заказы, производство. Роберт — система: GitHub, Claude Code, автоматизация, сайт, боты, приёмка процессов.
- Оба — не программисты. Пиши по-русски, коротко, простыми словами. Технический термин — только с объяснением в скобках.
- Если видишь способ лучше — скажи об этом одной фразой, но делай то, о чём просили.

## Где что лежит

| Сам репозиторий на компьютере | `~/kontent-zavod` | не на Рабочем столе и не в «Документах»: они синхронизируются с облаком, git там ломается |

Карта репозитория: `crm/` — схема учёта и скрипт `crm.py`; `processes/` — регламенты; `prompts/` — промты; `templates/` — шаблоны паспорта и ТЗ; `.claude/skills/` — команды `/клиент`, `/заказ`, `/релиз`. Позже появятся `site/`, `bots/`, `agents/`.

## Учёт: только через crm.py
Таблицу и общий диск агент меняет **только** командами `uv run crm/crm.py …` — не через браузер, не через коннектор Google Drive и не «по памяти». Скрипт сам даёт номера, проверяет значения по `crm/schema.toml`, создаёт папки и пишет каждое изменение в лист «Журнал».

| Задача | Команда |
|---|---|
| проверить доступы | `uv run crm/crm.py selftest` (`--full` — ещё и пробный прогон заказа в отдельной таблице; живой учёт не трогается) |
| проверить весь учёт | `uv run crm/crm.py check` |
| найти | `uv run crm/crm.py get Клиенты --where "Контакт=@anna"` · `get Заказы 0012-1` · `get Заказы --where "Статус!=выполнен"` |
| новый клиент | `uv run crm/crm.py add Клиенты --set "Имя=…" --set "Канал связи=Telegram" --set "Контакт=@…" --set "Источник=…"` |
| новый заказ | `uv run crm/crm.py add-order --client К-0007 --set "Канал=…" --set "Товар=…" --set "Состав=Карточка под ключ" --set "Порядок оплаты=…"` |
| ещё товар в тот же заказ | `… add-order --client К-0007 --to 0012 --set …` → номер 0012-2 |
| изменить | `uv run crm/crm.py set Заказы 0012-1 --set "Статус=в работе"` |
| файлы на Диск | `uv run crm/crm.py upload --order 0012-1 --sub ТЗ файл1 файл2` (`--client К-0007`, `--path "Обучение/…"`, `--replace` для замены, `--move` — удалить копию из `_work/` после проверки) |
| файлы с Диска | `uv run crm/crm.py download --order 0012-1 --sub Исходники --to _work/0012-1` |
| ссылка клиенту | `uv run crm/crm.py share 0012-1 preview` (на согласование) · `share 0012-1 result` (после оплаты) |
| пришли деньги | `uv run crm/crm.py pay 0012-1 --sum 6600 --method Продамус` (`--date дд.мм.гггг`, если не сегодня) · за весь заказ: `pay 0012 --sum …` — скрипт делит по товарам · возврат: `--refund` |
| отчёт к созвону / выплаты партнёрам / стоимость единицы | `uv run crm/crm.py report` (последние 7 дней) · `report --month 11.2026` |
| заплатили за нейросеть или сервис | `uv run crm/crm.py add Расходы --set "Статья=нейросети" --set "Сервис=Kling" --set "Сумма, ₽=2400"` (рекламу и выплаты партнёрам сюда не вносить) |
| выплатили партнёру | `uv run crm/crm.py add Выплаты --set "ID партнёра=П-0001" --set "За месяц=11.2026" --set "Сумма, ₽=…"` |
| новое размещение рекламы | `uv run crm/crm.py add Реклама --set "Площадка=Telegram-канал" --set "Канал или кампания=@…" --set "Расход, ₽=…" --set "ERID=…"` → код `R-0005` и готовые ссылки для поста |
| строка заведена руками без папки | `uv run crm/crm.py mkfolder Заказы 0012-1` |
| заказ сдан — убрать копии с компьютера | `uv run crm/crm.py clean` |
| партнёр, пробная обложка | `add Партнёры …` · `add "Пробные обложки" --set "Артикул WB=…"` |

Ответ скрипта — JSON. «ОШИБКА: …» значит, что **ничего не записано**: перескажи причину человеку простыми словами и не обходи её. `--force --reason "…"` — только если человек прямо сказал нарушить правило; причина попадёт в «Журнал».

Правила учёта (их же проверяет скрипт):
- Номера: клиент `К-0001`, заказ-товар `0012-1` (один заказ — один товар; второй товар того же заказа — `0012-2`), партнёр `П-0001`, размещение рекламы `R-0001` (латиницей — код идёт в ссылку). Номера даёт скрипт, их не меняют и не используют повторно. «k7», «К 7», «12-1», «р-5» скрипт понимает сам и приводит к одному виду.
- Значения столбцов со списком — только из списка (`crm/schema.toml` → `[lists]`). Даты — `дд.мм.гггг`. Деньги — целые рубли.
- Статус заказа: новая заявка → обсуждение → ждём материалы → в работе → на проверке → на согласовании → правки / согласовано → выполнен; отменён — из ранних этапов. «На проверке» — проверяет Кристина, клиенту уходит только после её «да».
- «В работе» — только когда заполнены Состав, К оплате, Порядок оплаты, Дедлайн; при «50 на 50» — ещё и после предоплаты 50% **всего заказа** (всех его товаров), внесённой командой `pay`. Сумму предоплаты называет `add-order` в ответе («предоплата за весь заказ 0012»; после последнего товара — итоговая) — её и пиши клиенту.
- «Цену по прайсу» и «Оплачено» считает только скрипт. «К оплате» он тоже считает сам по составу и скидке при каждой смене состава или скидки. Сумма ниже правил — только «Скидка=другая» с согласия Кристины, новой суммой и причиной в «Комментарии»; иначе ошибка «эскалация к Кристине».
- Правки: два круга бесплатно; при переводе в «правки» скрипт прибавляет круг сам; третий и дальше — 1 000 ₽ за круг: согласуй с клиентом и добавь «Доп. круг правок» в Состав — сумма пересчитается сама (скидка 10% на него не действует).
- Оплата: первые 10 внешних заказов (УК и Kwork места не занимают) — постоплата, дальше 50 на 50; заказы Kwork — «через Kwork», и только они. Деньги вносятся только командой `pay` — она пишет строку с датой в «Оплаты», пересчитывает «Оплачено» и «Статус оплаты». «Выполнен» и ссылка на «Результат» — только после полной оплаты.
- Скидка 10% — только на первый заказ клиента (на все его товары) и только с «Кейс = разрешил» (подписка на «Проще» и разрешение показать работу).
- SEO (и любой продукт с ценой 0 ₽) — только внутри пакета: отдельно в «Состав» не добавляется. Нужно SEO — предложи «Карточку под ключ».
- Код источника: в первом сообщении клиента ищи промокод партнёра или код вида `R-0005` (его подставляет ссылка из рекламы) и ставь в «Код источника»; кода нет — спроси «откуда узнали». Скрипт примет только существующий промокод или код.
- УК — внутренний заказчик (Источник «УК»): в цель 1 млн ₽ и в 10 заказов с постоплатой не входит.
- Перед любой записью покажи человеку, что запишешь, и дождись «да». Исключение — когда человек сам продиктовал точное значение.

## Файлы на Диске
- Папка заказа `Заказы/0012-1 Товар/`: `ТЗ` (тз.md по шаблону `templates/tz.md` и всё, что прислал клиент, как есть) · `Исходники` (имена из `processes/iskhodniki.md`: лист-ракурсов, фронт, 3-4-слева, 3-4-справа, бок, тыл, верх, в-руке, рядом-со-смартфоном, деталь-…, коробка-…, часть-…, раскладка-частей, паспорт.md, аналитика.md, seo.md) · `Работа` (черновики: Видео/Кадры, Видео/Клипы, Карусель/v1 …) · `На согласование` (фото чуть хуже исходного, видео с водяным знаком) · `Результат` (финальные файлы).
- Папка клиента `Клиенты/К-0007 Имя/`: переписка (`переписка дд.мм.гггг.md`), материалы бренда. Все диалоги сохраняем — это обучающая база будущего агента.
- Учебные товары — `Обучение/<товар>/` с той же структурой, что у заказа.
- Чужие материалы (конкуренты) — только для анализа, в `Работа/Исследование`; контент студии всегда свой.
- На компьютере файлы заказа лежат только в `_work/<номер>/` и только пока идёт работа: загрузил свой файл из `_work/` — `upload … --move`; заказ сдан или отменён — `uv run crm/crm.py clean`.

## Нельзя
- Класть в репозиторий фото, видео, документы клиентов, ключи, пароли, токены. Читать или выводить содержимое ключа агента.
- Удалять что-либо на Диске и в Таблице; менять заголовки и номера; заводить второй лист/таблицу «для удобства».
- Отправлять клиенту что-либо без подтверждения Кристины. Давать ссылку на «Результат» до оплаты.
- Писать в карточках и слайдах то, чего нет в паспорте товара.
- Пушить в `main` напрямую и делать `git push --force`.

## Если что-то сломалось
Скажи человеку прямо, что не получилось и почему, и остановись — не придумывай обходной путь. Частые случаи: нет ключа → его выдаёт Роберт; «заголовки не совпадают» → кто-то правил первую строку, верните как было; 403 → у агента нет доступа к общему диску; «ВНИМАНИЕ: правила не обновились» при старте → сообщи Роберту; «папка проекта лежит в синхронизируемой папке» → проект надо перенести в `~/kontent-zavod`, сообщи Роберту; `check` пишет «не совпадает с листом «Оплаты»» → кто-то вписал деньги руками: `pay <номер> --recalc`; `selftest --full` пишет «Таблица хранит значения не так…» → в живой учёт ничего не заводи, покажи ответ Роберту.

## Репозиторий: ветки, коммиты, релизы
- `main` — всегда рабочая версия. Любое изменение — в отдельной ветке: `process/…`, `prompt/…`, `skill/…`, `crm/…`, `site/…`, `agent/…`, `fix/…` (латиницей: в ссылках и командах кириллица ломается и путается с похожими буквами).
- Одно логическое изменение — один коммит. Сообщение по-русски: `тип(область): что сделано`. Типы: процесс, промт, навык, crm, сайт, агент, исправление, документация. В теле — зачем и шаг/раздел плана. Пример: `процесс(видео): добавлен шаг склейки по последнему кадру`.
- В `main` — только через запрос на слияние (`gh pr create`); проверяет и принимает Роберт.
- Шапка каждого регламента: `Версия N от дд.мм.гггг`. В начале каждого скрипта — назначение, вход, выход.
- Релиз — по вторникам перед созвоном, если в `main` есть изменения: тег `v0.N` + запись в `CHANGELOG.md` (навык `/релиз`). v1.0 — система после MVP (10 заказов). Сайт публикуется только из релиза.
- Изменения схемы учёта (`crm/schema.toml`) — только Роберт: новый столбец — в конец листа, затем `uv run crm/crm.py setup`.
- Всё, что появится на серверах (сайт, боты, агенты), Роберт заносит в свой реестр серверов (`~/Desktop/Серверная`).
