# CLAUDE.md — правила проекта «Контент завод»

Студия контента для продавцов маркетплейсов: видео, карусели, интерьерные фото, RICH, SEO, коробки и инструкции. Главный документ — бизнес-план v18. Этот файл Claude Code читает сам в начале каждой сессии; люди читают его же.

Студия — направление УК BlackRED (с 09.11.2026), описание направления — `~/Desktop/УК В Китае/контент-завод/` (у Роберта). Сотрудник работает в двух линиях по одним правилам: **товары УК** — компании фабрик под управлением BlackRED и наши компании, и **товары клиентов студии** — внешние продавцы по прайсу.

## Кто и как
- Кристина — руководитель студии: клиенты, заказы, производство, проверка результата. Роберт — система: GitHub, Claude Code, CRM, автоматизация, сайт, приёмка процессов. Контент товаров УК делают и менеджеры отдела продаж.
- Все — не программисты. Пиши по-русски, коротко, простыми словами. Технический термин — только с объяснением в скобках. Сотрудники часто говорят голосом: ошибки распознавания понимай по смыслу.
- Если видишь способ лучше — скажи одной фразой, но делай то, о чём просили.

## Как работаем: «скажи, что нужно»
Сотрудник говорит обычными словами: «сделай инфографику для HD2000», «видеообложка на К-0007-1», «что готово по soundbar_V8». Навык **`/kontent`** сам находит товар в CRM, проверяет обязательный набор файлов в папке товара (нет — стоп и список, чего не хватает), запускает навык производства, показывает результат на ноутбуке и после «готово» сотрудника кладёт его в папку вида товара — CRM сама даёт имя файлу и заводит запись учёта. Общие правила для всех навыков производства — **`processes/obshchie-pravila.md`**.

## CRM: только через MCP
- Записи в CRM — только действиями MCP `uchet`, не через браузер и не «по памяти». Перед `create`, `update`, `remove` покажи человеку, что будет сохранено, и дождись «да». После записи дай ссылку на карточку и перескажи заметки сервера.
- Отказ CRM («нет прав», «не сохранено: …») — перескажи словами, ничего не записано; правило не обходи.
- Номера даёт CRM: клиент `К-0007`, товар клиента `К-0007-1`, заказ `0012`. Товар УК — по артикулу (`soundbar_V8`).
- Правила плана студии (прайс, постоплата, 50 на 50, скидка 10 %, круги правок) CRM не проверяет — их держит агент по `processes/zakaz.md`.

## Нельзя
- Класть в репозиторий фото, видео, документы товаров и клиентов, ключи, пароли, токены. Исключение — образцы стиля навыков (`.claude/skills/*/assets/`) и картинки сайта (`site/`).
- Удалять или перезаписывать что-либо в папках товаров; менять имена папок, которые создала CRM.
- Отправлять клиенту что-либо без подтверждения Кристины. Давать ссылку на результат до оплаты.
- Писать в карточках, слайдах, видео, на коробке то, чего нет в паспорте товара.
- Тратить деньги (платные генерации, кредиты, подписки) без согласования.
- Пушить в `main` напрямую и делать `git push --force`.

## Если что-то сломалось
Скажи человеку прямо, что не получилось и почему, и остановись — не придумывай обходной путь. Частые случаи: MCP `uchet` не отвечает или «нет прав» → ключ ИИ выдаётся в кабинете CRM («Мой аккаунт»), права — у Роберта; `content_files` не показывает папку товара или «нет прав» → раздел не открыт сотруднику в CRM — сообщи Роберту (обходить через Диск или браузер нельзя); «ВНИМАНИЕ: правила не обновились» при старте → сообщи Роберту; репозиторий открыт с Рабочего стола или из облачной папки → его надо перенести в `~/kontent-zavod`.

## Репозиторий: ветки, коммиты, релизы
- `main` — всегда рабочая версия. Любое изменение — в отдельной ветке: `process/…`, `prompt/…`, `skill/…`, `site/…`, `agent/…`, `fix/…` (латиницей).
- Одно логическое изменение — один коммит. Сообщение по-русски: `тип(область): что сделано`. Типы: процесс, промт, навык, сайт, агент, исправление, документация. В теле — зачем.
- В `main` — только через запрос на слияние (`gh pr create`); проверяет и принимает Роберт.
- Шапка каждого регламента: `Версия N от дд.мм.гггг`.
- Улучшение навыка по правке человека — та же ветка `skill/…`: правку, которую пришлось делать руками, записываем в навык так, чтобы она больше не понадобилась.
- Релиз — по вторникам, если в `main` есть изменения: тег `v0.N` + запись в `CHANGELOG.md` (навык `/релиз`). Сайт публикуется только из релиза.
- Всё, что появится на серверах (сайт, боты, агенты), Роберт заносит в реестр серверов.
