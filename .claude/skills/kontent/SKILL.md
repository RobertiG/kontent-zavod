# /kontent — «скажи, что нужно, остальное я сам»

Вход: $ARGUMENTS. Сначала прочитай `processes/obshchie-pravila.md` — там линии УК и студии, подпапки, доступ к файлам, генераторы, деньги и проверка. Сотрудник часто говорит голосом: ошибки распознавания («инфа графика», «рич», «видео обложка», «аш дэ две тысячи») понимай по смыслу и не переспрашивай из-за них.

## 1. Понять, что сделать

| Сотрудник говорит | Вид | Навык |
|---|---|---|
| исходники, паспорт, фото на белом, фото со всех сторон | исходники и паспорт | `pasport-tovara` |
| аналитика, конкуренты, ниша | аналитика | `analitika` |
| SEO, название и описание, ключевые слова | SEO | `seo` |
| инфографика, карусель, слайды, воронка, главное фото | инфографика | `infografika` |
| интерьерные фото, товар в интерьере, в жизни | интерьерные фото (5 / 10 / 15) | `interer` |
| видеообложка, обложка 6 сек, оживи обложку | видеообложка | `videooblozhka` |
| видео, ролик 15 / 30 / 60 | видео | `video` |
| RICH, рич, расширенное описание | RICH | `rich` |
| коробка, упаковка, инструкция | коробка и инструкция (или одно из них) | `box-manual-layout` |
| стайлгайд, дизайн-система, фирменный стиль | стайлгайд | `staylgayd` |
| «карточка под ключ» | пакет | по очереди: `pasport-tovara` → `analitika` → `seo` → `infografika` → `videooblozhka` → `video` (30 сек) → `rich` |
| «всё включено» | пакет | карточка под ключ + `box-manual-layout` + `staylgayd` |
| «что готово», «что есть», «чего не хватает» по товару | только отчёт | шаги 2–3, без производства; ответ — таблица по видам из общих правил, §2: есть (дата, сколько файлов) / нет / можно начать сразу или что сначала |
| «переделай», «поправь слайд 3: …» | правка | навык того вида, только указанное (см. «Правки») |

Не ясен вид или товар — один короткий вопрос с вариантами. Остальное не спрашивай.

Строка заказа студии называется как в прайсе: «Карусель» → `infografika`, «Обложка 6 сек» → `videooblozhka`, «Видео 15/30/60 сек» → `video`, «Интерьерные фото» → `interer`, «RICH-контент» → `rich`, «Коробка», «Инструкция», «Коробка + инструкция» → `box-manual-layout`, «Стайлгайд» → `staylgayd`, «Карточка под ключ» и «Всё включено» — пакеты; исходники, паспорт, аналитика и SEO отдельными строками не продаются — делаются внутри заказа.

## 2. Найти товар в CRM (MCP `uchet`)

1. Номер вида `К-0007-1` → сразу `get studio_products`. Иначе ищи в обоих разделах: `find content_products` и `find studio_products` с `query` = артикул, модель или название. Модель («HD2000») может быть частью артикула или названия.
2. Одна запись — берём. Несколько — покажи списком (ID, название, проект или клиент) и спроси, какая. Ни одной — скажи, кто заводит: товар УК — Продуктовый отдел в справочнике CRM (раздел `products`); товар клиента — `/клиент`, затем товар клиента. Сам товар не заводи без «да».
3. Запомни: ID, название, линию (УК или студия), ссылку на папку товара. Для студии — открой клиента (`get studio_clients`) и его незакрытые заказы (`get studio_orders`): найди строку заказа (`studio_lines`) с этим товаром и этой работой.
4. Папка товара — только через MCP (общие правила, §3): `content_files(product=<ID>)`. Папки ещё нет — товар новый, исходников нет; она появится при первой загрузке.
5. Площадку товара (у товара клиента — поле «площадка») запомни и передай навыкам: аналитика, инфографика и RICH делаются под неё, а не под обе.

## 3. Опись папки и проверка исходников

Опись папки — `content_files` (общие правила, §3): верхний уровень, затем каждая подпапка. Опись: по каждой подпапке — свежая папка версии и её файлы. Сверь с тем, что нужно виду:

| Навык | Что должно быть | Чего нет → что делаем |
|---|---|---|
| `pasport-tovara` | в «Материалах от фабрики / клиента»: фото товара со всех сторон (любые, можно с телефона); желательно инструкция, коробка, характеристики, ссылка на карточку | нет фото → стоп, попросить по списку съёмки (`processes/iskhodniki.md`, шаг 1) |
| `analitika` | свежий паспорт (`паспорт.md` или `Паспорт_*.pdf` — общие правила, §2) или хотя бы материалы товара | паспорта нет → аналитика по материалам; внутри `pasport-tovara` она запускается сама по черновику блоков 1–8 |
| `seo` | паспорт и аналитика не старше 30 дней | → сначала то, чего нет |
| `infografika` | паспорт и фото 01–07; аналитика или конкурентный раздел паспорта не старше 30 дней (нет — навык сделает `analitika` сам) | → сначала `pasport-tovara` |
| `interer` | паспорт, фото `01_front`, `04_angle45`, `05_scale` | → `pasport-tovara` |
| `videooblozhka` | `01_main.jpg` в свежей «Карточка товара / Инфографика — …» | → `infografika` (и по цепочке дальше) |
| `video` | паспорт и фото; аналитика желательна | → `pasport-tovara` |
| `rich` | свежая инфографика; интерьерные фото — желательно | → `infografika` |
| `box-manual-layout` | паспорт и фото; в «Материалах»: инструкция изготовителя (китайская подходит), заводская развёртка коробки с размерами, штрихкод, QR поддержки (если были) | нет развёртки → коробка только как концепция граней с пометкой «не для печати»; нет инструкции изготовителя → спросить |
| `staylgayd` | логотип и материалы бренда в «Материалах» | → спросить |

- **Цепочку запускай сам**, без отдельного вопроса, если для её первого шага всё есть: одной строкой скажи план («Исходников нет — сначала паспорт и фото, потом инфографика») и начинай. Цепочка идёт как пакет (см. ниже).
- **У клиента студии** недостающий шаг может быть отдельным продуктом прайса (заказали видеообложку без карусели). Такого шага нет в заказе — не делай его молча: спроси «добавить строку «Карусель» в заказ или взять главное фото с карточки клиента?». Исходники, паспорт, аналитику и SEO делай без вопроса — они входят в любой заказ.
- Спрашивай только то, без чего нельзя: нет фото товара, нет развёртки коробки, платный шаг, противоречие в данных.
- Паспорт и фото свежие, пока товар не менялся; аналитика — 30 дней, старше — обнови.

## 4. Запуск

1. Студия: перед «в работе» открой заказ (`get studio_orders`): поле «порядок оплаты» = «50 на 50» и оплачено меньше 50 % всего заказа — статус не ставь и скажи Кристине (правила — `processes/zakaz.md`). Иначе строка заказа → «в работе» (одно согласие на оба статуса — общие правила, §3). Строки нет — скажи, что заказ заводит `/заказ`; делать можно, если сотрудник так сказал.
2. Скачай через `content_download` в `_work/<ID>/вход/` только то, что нужно виду, — не всю папку. Для инфографики, интерьера, видео, RICH, коробки и инструкции добавь свежий `стайлгайд.md`, если он есть (общие правила, §2).
3. Запусти навык вида (инструмент Skill). Передай: ID и название товара, линию, путь `_work/<ID>/`, куда положить готовое — `_work/<ID>/готово/<Подпапка>/<Папка версии>/` по таблице общих правил, §2. Навык работает с `_work`, а не с Рабочим столом.

## 5. Сохранение и отчёт

1. Загрузи каждый файл из `_work/<ID>/готово/<Подпапка>/<Папка версии>/` через `content_upload` — по одному, в ту же папку версии. Затем `content_files` этой папки: все файлы на месте, размеры совпадают — «сохранено» (общие правила, §3).
2. Студия: строка заказа → «на проверке». Проверяет Кристина; клиенту ничего не уходит.
3. Отчёт по общим правилам, §7, со ссылкой на папку товара.
4. Удали `_work/<ID>/` — один раз, когда вся работа по товару закончена (в цепочке — после последнего шага).

## Пакет, несколько товаров, правки

- **Пакет и цепочка** — шаги по очереди. После каждого навыка — §5.1–5.2 (сохранение в папку товара), затем его результат копируется из `готово/` во `вход/` следующего шага. Сорвётся середина — сделанное не потеряется. В конце — один общий отчёт и удаление `_work/<ID>/`.
- **Несколько товаров** — по одному; независимые генерации разных товаров можно вести параллельно в разных вкладках.
- **Правки** («слайд 3: нож слишком большой») — тот же навык, только названное; новая папка версии с временем в имени, остальные файлы скачиваются из прошлой версии и загружаются в новую без изменений. Правка повторяется второй раз — предложи дописать её в навык, чтобы не повторялась.
