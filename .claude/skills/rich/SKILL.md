# RICH-контент

Регламент — `processes/interer-rich.md` (раздел «RICH-контент»). RICH раскрывает подробнее то, что карусель показывает коротко, и забирает интерьерные фото, которые не поместились в галерею Ozon.

## Запуск

Прочитай `processes/obshchie-pravila.md`. Обычно навык запускает `/kontent`: находит товар в CRM, скачивает нужное в `_work/<ID>/вход/`, а после «готово» сотрудника загружает `_work/<ID>/готово/` в CRM. Вызвали напрямую по названию товара — сначала шаги 1–4 `/kontent`.

## Что нужно на входе

- Обязательно: паспорт и фото `01`–`07` (общие правила, §2б).
- Желательно: свежая инфографика — стиль (палитра, шрифт, плашки) и мастер главного фото без надписей. Нет — стиль из выбранного стайлгайда или стандарта, товар — фото `01`–`07`.
- Желательно: актуальные интерьерные фото и их полноразмерные мастера (`find content_items` с `kind: "interer"`, `masters: "да"`).
- Паспорт (характеристики, комплект, размеры), `аналитика.json` (порядок аргументов, боли), `seo.md` — для подписей, если есть (нет — подписи из паспорта).
- Стиль: `стайлгайд.md`, если есть; у товаров BlackRED — `infografika/references/visual-standard.md`.

## Шаги

1. **Требования на дату.** Открой официальную документацию: Ozon — rich-content.ozon.ru (описание JSON, песочница, требования к картинкам), WB — справка WB Partners «Рич-контент» (`processes/interer-rich.md`, «Где учиться»). Выпиши в `работа/требования.md` со ссылками и датой: размеры картинок для компьютера и телефона, форматы, вес файла, число блоков, нужные поля JSON. По памяти формат не берём: схема Ozon меняется. Справка закрыта входом или CAPTCHA — попроси человека открыть её; без подтверждённых требований делай баннеры, а JSON помечай «не проверен».
2. **Структура.** 5–8 экранов, ориентир порядка: герой и главная польза → 2–3 выгоды с доказательством (по аналитике) → товар в жизни (интерьерные фото) → детали и как работает → характеристики → комплект и размеры. Не повторяй карусель кадр в кадр: один экран — одна мысль, раскрытая подробнее. Текст — только из паспорта. Сохрани `структура.md`.
3. **Вёрстка.** Каждый баннер — HTML-файл: картинка товара — фото 01–07, полноразмерные мастера интерьерных фото и мастер главного фото без надписей (мастер записи `01-main` инфографики); готовые слайды с впечатанным текстом не берём — выйдет двойной текст. Товар на них уже проверен — не перегенерируем; текст живым текстом, цвета, шрифт и плашки — из стайлгайда, а без него — из концепции инфографики. Отрисуй в PNG браузером (скриншот страницы нужного размера). Нужен новый фон или сцена — генерируй по правилам навыка `interer`. Версии для компьютера и телефона — если площадка их требует.
4. **JSON для Ozon.** Собери по описанию из шага 1. Адреса картинок: как их получить (загрузка в конструктор или хранилище Ozon) — по документации; сами ничего не загружаем, поэтому в JSON ставим имена файлов как заглушки, а в `rich.md` пишем, куда подставить адреса. Проверь: JSON открывается (`python3 -m json.tool rich_ozon.json`); если песочница rich-content.ozon.ru доступна без входа в кабинет — вставь туда для предпросмотра, ничего не сохраняя в карточку.
5. **Набор для WB** — картинки по требованиям WB на дату, по порядку экранов.
6. **Превью.** `превью.html` — локальная страница: блок Ozon и блок WB по порядку, в ширину компьютера и телефона. Открой её в браузере и проверь глазами (скриншот). Это наше приближение, не отрисовка площадки.

## Что получаем

Папка `_work/<ID>/готово/rich/` (общие правила, §2):

- `ozon-01.png` … — баннеры Ozon, назначение «RICH Ozon — экран 1»; `ozon.json` — разметка Ozon;
- `wb-01.jpg` … — баннеры WB (формат файлов — по требованиям на дату);
- `rich.md` — порядок экранов, тексты, требования со ссылками, что и куда подставить при загрузке. Загружает на площадку человек.
- `Мастера/ozon-01.html` … — HTML каждого баннера, мастер к нему: по нему правят текст без новой генерации.
- В `based_on` — id использованных слайдов, интерьерных фото и мастеров; в описание баннера — тексты, палитра, шрифт, источник картинки товара.
- `превью.html` (просмотр обоих блоков), `требования.md`, `структура.md`, `проверка.md` — в `_work/<ID>/работа/`, в CRM не идут.

## Проверка

- [ ] Тексты совпадают с паспортом, без опечаток, читаются на телефоне.
- [ ] Товар на баннерах — с проверенных слайдов и фото, не изменён; масштаб верный.
- [ ] Размеры, форматы и вес файлов — по требованиям на дату; у каждого требования есть ссылка.
- [ ] JSON открывается; все картинки, на которые он ссылается, лежат в папке; результат песочницы записан (или «песочница недоступна»).
- [ ] `превью.html` открывается, порядок экранов логичный, нет повторов карусели.
- [ ] На площадки ничего не загружено.

## Если не получилось

- **Нет инфографики или интерьерных фото** — RICH без них, это не блокер. Нет паспорта или фото `01`–`07` — стоп по общим правилам, §2б.
- **Документация недоступна** — баннеры делаем, JSON с пометкой «не проверен по документации на дату».
- **Песочница ругается на JSON** — исправь по тексту ошибки; после двух неудачных попыток сохрани последнюю версию и перескажи ошибку человеку.
- **Рич-контент на WB продавцу недоступен или платный** — решает человек; набор картинок всё равно готов.
