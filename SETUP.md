# Настройка ноутбука сотрудника студии

Версия 2 от 12.11.2026 (вместо `AGENT-KRISTINA.md`: учёт перешёл в CRM УК через MCP). Сотрудник отдаёт этот файл своему Claude; Claude по нему настраивает себя сам и проверяет, что всё работает.

## Часть 1. Для сотрудника

Что получится: вы говорите Claude обычными словами, какой контент нужен и для какого товара, — он сам находит товар в CRM, проверяет исходники, делает контент и кладёт его в папку товара на Google Диске. Вам остаётся проверить результат и сказать, что поправить.

Нужно заранее (выдаёт или подтверждает Роберт):
1. Подписка Claude **Pro или Max** и приложение Claude для компьютера (claude.com/download) — во вкладке **Code** работает Claude Code.
2. Аккаунт GitHub и принятое приглашение в репозиторий `RobertiG/kontent-zavod` (письмо от GitHub → «Accept invitation»).
3. Вход в CRM (system.black-red.com) с доступом к Продуктовому отделу и/или студии. В кабинете CRM → «Мой аккаунт» → «Выпустить ключ» — там же готовая строка подключения для Claude Code. Ключ личный: никому не пересылайте и не вставляйте в чат.
4. Google-аккаунт, которому открыты общие диски «Студия дизайна» и/или «BlackRED» — чтобы открывать результат по ссылке из CRM. Файлы агент берёт и кладёт сам через CRM.
5. Подписка Gemini Pro (генерация изображений и видео) — вход под тем же Google-аккаунтом. ChatGPT — по желанию.

Как начать: Claude → **Code** → **Local** → **Select folder** → создайте пустую папку «Настройка» → перетащите этот файл в окно → напишите: «Настрой себя по этому файлу». Займёт 20–40 минут; руками нужно будет нажать «Установить», ввести пароль компьютера, войти в GitHub и в Google, один раз выполнить строку из кабинета CRM.

Потом каждый день открывайте в Code папку **kontent-zavod** в домашней папке и говорите:

| Вы говорите | Claude делает |
|---|---|
| «Сделай паспорт и фото для HD2000» | находит товар в CRM, берёт «Материалы от фабрики», делает паспорт и 7 фото на белом, кладёт в «Исходники» |
| «Инфографика для К-0007-1» | проверяет обязательные файлы (нет — скажет, чего не хватает), делает главное фото и слайды, показывает на ноутбуке; после вашего «готово» кладёт в «Карточку товара» |
| «Карточка под ключ для soundbar_V8» | по очереди: исходники, аналитика, SEO, инфографика, видеообложка, видео 30 сек, RICH |
| «Что готово по HY1000?» / «Чего не хватает для коробки?» | опись папки товара и чего не хватает |
| «Слайд 3: нож слишком большой, сделай вдвое меньше ладони» | переделывает только этот слайд новой версией |
| «Новый клиент, вот переписка: …» / «Занеси заказ: …» / «Клиент оплатил 6 600» | клиент, товар клиента, заказ, оплата в CRM — после вашего «да» |

## Часть 2. Для агента: настройка

Правила: шаги по порядку; после каждого — проверка; не прошла — **остановись**, объясни простыми словами, что не так и кто поможет (обычно Роберт). Говори по-русски, без технических слов; перед установкой скажи одной фразой, что и зачем. Никогда не проси ключ CRM в чат и не выводи его. Команды — для macOS; для Windows — вариант после «Windows:».

**Шаг 0. Где ты работаешь.** `echo ok` выполняется? Нет (обычный чат) — «Откройте Claude → Code → Local → Select folder и повторите». Система: `uname -s`.

**Шаг 1. Инструменты:** git и gh (версии правил и GitHub), ffmpeg (видео), ImageMagick (сравнение картинок), poppler (просмотр PDF).
- Mac: `xcode-select --install` (если нет git), Homebrew (brew.sh), затем `brew install gh ffmpeg imagemagick poppler node uv` (node — для плагина браузера, uv — для проверочных скриптов) и Google Chrome (google.com/chrome). Windows: `winget install --id Git.Git -e`, `winget install --id GitHub.cli -e`, `winget install --id Gyan.FFmpeg -e`, `winget install --id ImageMagick.ImageMagick -e`, poppler — по ссылке из `winget search poppler`.
- Проверка: `git --version && gh --version && ffmpeg -version | head -1 && magick -version | head -1 && pdftoppm -v && node -v && uv --version`.

**Шаг 2. GitHub и репозиторий.** `gh auth status`; не вошли — `gh auth login --hostname github.com --git-protocol https --web` (покажи код из 8 знаков, сотрудник вводит его на странице), затем `gh auth setup-git`. Затем `cd ~ && gh repo clone RobertiG/kontent-zavod` — только в домашнюю папку, не на Рабочий стол, не в «Документы», iCloud, OneDrive, Яндекс Диск.
- Проверка: есть `~/kontent-zavod/CLAUDE.md`. Ошибка 404 — приглашение не принято.

**Шаг 3. CRM через MCP.** Попроси сотрудника: «Откройте CRM → «Мой аккаунт» → «Выпустить ключ», скопируйте строку для Claude Code. Откройте программу «Терминал» (Windows — PowerShell), введите `cd ~/kontent-zavod` и нажмите Enter, затем вставьте строку и нажмите Enter». Строка вида `claude mcp add --transport http uchet https://system.black-red.com/mcp --header "Authorization: Bearer <ключ>"` — имя подключения должно быть **uchet**: на него опираются навыки. `cd` обязателен: без `--scope user` в строке подключение привязывается к той папке, где его выполнили, и в `kontent-zavod` его не будет. Ключ в чат не просить.
- Проверка: `cd ~/kontent-zavod && claude mcp list` — `uchet … ✓ Connected`; затем в следующей сессии вызов `whoami` называет сотрудника и открытые разделы (нужны `content_products` и/или `studio_*`).

**Шаг 3а. MPStats** (аналитика и SEO). Строку подключения `claude mcp add --scope user --transport http mpstats "https://mcp.mpstats.io/mcp?token=<токен>&tools=all"` с токеном даёт Роберт — сотрудник выполняет её в «Терминале» сам, токен в чат не вставлять. Имя подключения — **mpstats**. Проверка: `claude mcp list` — `mpstats … ✓ Connected`. Без него аналитика идёт по страницам маркетплейсов, частоты запросов не проверены.

**Шаг 4. Файлы товаров — через CRM.** Ставить ничего не нужно: опись, скачивание и загрузка файлов папки товара идут через MCP `uchet` (`content_files`, `content_download`, `content_upload`). «Google Диск для компьютера» не ставим.
- Проверка (в сессии шага 8): `content_files` по любому открытому сотруднику товару показывает подпапки товара. «Нет прав» — Роберту: открыть раздел «Контент по товарам» и/или студию.

**Шаг 5. Браузер для генерации.** Нужен плагин Claude Code **chrome-devtools-mcp** (`/plugin` → claude-plugins-official → chrome-devtools-mcp → установить; в настройках проекта он уже указан). Google не пускает в Chrome, который запущен плагином, поэтому вход делается так: закрыть Chrome плагина (`pkill -f chrome-devtools-mcp/chrome-profile`), запустить обычный Chrome с тем же профилем — `open -na "Google Chrome" --args --user-data-dir="$HOME/.cache/chrome-devtools-mcp/chrome-profile" --password-store=basic --use-mock-keychain` — сотрудник входит в Google и открывает gemini.google.com, затем закрыть этот Chrome (`pkill -TERM -f chrome-devtools-mcp/chrome-profile`), чтобы вход сохранился.
- Проверка: плагин открывает gemini.google.com уже с входом, видна подписка Pro.

**Шаг 6. Навыки документов.** В приложении Claude → Настройки → Возможности включить навыки работы с PDF и Word (нужны паспорту, коробке и инструкции). Нет такого пункта — скажи Роберту.

**Шаг 7. Передача в рабочую папку.** Скажи сотруднику дословно:
> Настройка почти готова. Откройте рабочую папку: Claude → Code → новая сессия → Local → Select folder → папка **kontent-zavod** в вашей домашней папке. На вопрос о доверии — «Доверять». Напишите: **«Закончи настройку по SETUP.md, шаг 8»**. Эту сессию можно закрыть.

**Шаг 8 (новая сессия в `kontent-zavod`).** Шаги 0–7 уже сделаны.
- `pwd` кончается на `kontent-zavod` и не в облачной папке.
- MCP `uchet`: `whoami` — ответ с именем сотрудника.
- Назови сотруднику три правила из CLAUDE.md своими словами: клиенту ничего не уходит без «да» Кристины; в карточках только то, что есть в паспорте; деньги на генерации — только с согласия.
- Спроси: «Наберите / — есть ли в списке /kontent, /клиент, /заказ?».
- Пробный запуск без записи: `/kontent что готово по <любой товар, открытый сотруднику>` — опись папки товара. Видно файлы — всё работает.

## Часть 3. Если что-то не так

| Сообщение | Что значит | Что делать |
|---|---|---|
| `uchet` не подключён / «нет прав» | нет ключа или раздел не открыт | ключ — «Мой аккаунт» в CRM; права — Роберту |
| не видна папка товара / «нет прав» на файлы | раздел товара не открыт сотруднику в CRM | доступ — Роберту |
| Gemini просит войти | слетел вход в браузере плагина | шаг 5 |
| Gemini «лимит исчерпан» | кончился лимит подписки (~25 картинок за окно) | подождать сброса; генерировать партиями |
| «ВНИМАНИЕ: правила не обновились» | на компьютере правки, которых нет в GitHub | `git status`, показать Роберту, ничего не удалять |
| в меню «/» нет `/kontent` | открыта не та папка или ей не доверились | новая сессия в `kontent-zavod`, «Доверять» |
| ошибка хука при запуске (Windows) | автообновление правил написано для bash | в `.claude/settings.local.json` записать `{"disableAllHooks": true}`; в начале дня говорить «обнови правила» |
