# Настройка компьютера сотрудника студии

Версия 5 от 13.11.2026: студия ставится в рабочую папку сотрудника — его правила сохраняются в `CLAUDE.local.md`; облако проверяется по факту; настройка по этапам, подключения — только для папки студии. Сотрудник отдаёт этот файл (или ссылку https://raw.githubusercontent.com/RobertiG/kontent-zavod/main/SETUP.md) своему Claude или Codex; помощник по нему настраивает себя сам и проверяет, что всё работает.

## Часть 1. Для сотрудника

Что получится: вы говорите помощнику обычными словами, какой контент нужен и для какого товара, — он сам находит товар в CRM, проверяет исходники, делает контент и кладёт его в папку товара на Google Диске. Вам остаётся проверить результат и сказать, что поправить.

Нужно заранее (выдаёт или подтверждает Роберт):
1. Подписка Claude **Pro или Max** и приложение Claude для компьютера (claude.com/download) — во вкладке **Code** работает Claude Code. Работаете в Codex — вместо этого подписка ChatGPT Plus или выше (часть 4).
2. Вход в CRM (system.black-red.com) с доступом к Продуктовому отделу и/или студии. Ключ для помощника — в кабинете CRM → «Мой аккаунт». Ключ личный: никому не пересылайте и не вставляйте в чат.
3. Google-аккаунт, которому открыты общие диски «Студия дизайна» и/или «BlackRED», и подписка Gemini Pro под ним.
4. Строка подключения MPStats от Роберта (аналитика) — можно позже.

Аккаунт GitHub не нужен: навыки скачиваются без входа.

Как начать: откройте Claude (Code → Local → Select folder) или Codex в своей рабочей папке и отправьте сообщение от Роберта. Помощник поведёт по этапам: перед каждым скажет, что будет и зачем. Займёт 20–40 минут; руками — нажать «Установить», ввести пароль компьютера, войти в Google, один раз выполнить строку из «Мой аккаунт».

Потом каждый день открывайте помощника в **папке студии** (её назовёт помощник в конце настройки) и говорите:

| Вы говорите | Помощник делает |
|---|---|
| «Сделай паспорт и фото для HD2000» | находит товар в CRM, берёт «Материалы от фабрики», делает паспорт и 7 фото на белом, показывает; после вашего «готово» кладёт в «Исходники» |
| «Инфографика для К-0007-1» | проверяет обязательные файлы (нет — скажет, чего не хватает), делает главное фото и слайды, показывает; после «готово» кладёт в «Карточку товара» |
| «Карточка под ключ для soundbar_V8» | по очереди: исходники, аналитика, SEO, инфографика, видеообложка, RICH (видео 30 сек — когда подключат Kling) |
| «Что готово по HY1000?» / «Чего не хватает для коробки?» | опись товара и чего не хватает |
| «Слайд 3: нож слишком большой, сделай вдвое меньше ладони» | переделывает только этот слайд |
| «Новый клиент, вот переписка: …» / «Занеси заказ: …» / «Клиент оплатил 6 600» | клиент, товар клиента, заказ, оплата в CRM — после вашего «да» |

## Часть 2. Для помощника: настройка

**Как вести настройку.** По этапам из таблицы. Перед каждым этапом скажи сотруднику простыми словами, без технических слов: что сейчас будет, зачем и что будет недоступно или станет работать иначе, если этап пропустить (столбец «Без этого»). Дождись «да» или «пропустить». После этапа — проверка и одна строка итога: «Готово: …» или «Пропущено: …, поэтому …». Уже сделанное (сотрудник работал с CRM раньше) — проверь и скажи «уже настроено». Проверка не прошла — остановись, объясни, что не так и кто поможет (обычно Роберт). В конце — сводка: что настроено, что пропущено и что из-за этого не работает.

Нельзя: просить ключи и токены в чат и выводить их; подключать что-либо «для всего компьютера» и переносить подключения из других папок — подключение действует только в той папке, где его сделали, пока сотрудник сам не попросит иначе; менять чужие подключения и входы на компьютере — нашёл такие, спроси. Команды — для macOS; для Windows — вариант после «Windows:».

| Этап | Что делаем | Зачем | Без этого |
|---|---|---|---|
| 0. Где работаем | проверяем, что помощник выполняет команды | без этого настроить ничего нельзя | настройка невозможна |
| 1. Программы | ставим недостающие программы | см. шаг 1 — у каждой своя задача | см. шаг 1 — по каждой программе |
| 2. Папка студии | скачиваем навыки и правила студии | по ним помощник делает контент; правила обновляются сами | студии нет — контент не делается |
| 3. CRM | подключаем CRM в папке студии | найти товар, скачать исходники, загрузить готовое | контент делать нельзя: нет доступа к файлам товаров |
| 4. MPStats | подключаем аналитику маркетплейсов | частоты запросов, продажи конкурентов, отзывы — для аналитики и SEO | аналитика — по страницам площадок, частоты не проверены, SEO слабее |
| 5. Gemini в браузере | вход в Google в браузере помощника | рисовать картинки (в Claude) и делать видеообложку | в Claude — нет картинок и видеообложки; в Codex — нет видеообложки |
| 6. Навыки PDF и Word | включаем в настройках Claude (только Claude) | паспорт, коробка и инструкция в PDF и Word | PDF и Word собираются запасным способом, дольше |
| 7. Новая сессия | открываем помощника заново в папке студии | правила студии включаются только при запуске в её папке | навыки студии не видны |
| 8. Проверка | пробный запрос в CRM, сводка | убедиться, что всё работает | — |

**Шаг 0. Где ты работаешь.** `echo ok` выполняется? Нет (обычный чат) — «Откройте Claude → Code → Local → Select folder и повторите». Система: `uname -s`. Текущая папка: `pwd`.

**Шаг 1. Программы.** Сначала проверь, какие уже стоят: `git --version; magick -version; ffmpeg -version; pdftoppm -v; node -v; uv --version` и есть ли Google Chrome. Затем скажи: «Сейчас по инструкции будут установлены дополнительные программы: <только недостающие>. Они ставятся один раз на компьютер, личных данных в них нет. Установка займёт 5–15 минут, система может попросить пароль компьютера». Что даёт каждая и что будет без неё:

| Программа | Для чего | Без неё |
|---|---|---|
| git | скачивает и обновляет навыки студии | настройка невозможна |
| ImageMagick | сравнивает картинку с оригиналом товара, меняет размер, собирает превью | картинки нельзя проверить — паспорт с фото, инфографика, интерьер, RICH недоступны |
| ffmpeg | обрезает и проверяет видео | видеообложка недоступна |
| poppler | читает PDF: паспорт, инструкции фабрики, проверка страниц | PDF не читаются — коробка, инструкция и паспорт из PDF недоступны |
| Node | нужен браузеру, через который Claude работает с Gemini | в Claude нет картинок и видеообложки |
| uv | запускает проверочные скрипты (размеры слайдов) | проверка слайдов только глазами |
| Google Chrome | браузер для Gemini | как без Node |

- Mac: `xcode-select --install` (если нет git), Homebrew (brew.sh), затем `brew install` недостающего из `ffmpeg imagemagick poppler node uv`; Chrome — google.com/chrome. Windows: `winget install --id Git.Git -e`, `winget install --id Gyan.FFmpeg -e`, `winget install --id ImageMagick.ImageMagick -e`, `winget install --id OpenJS.NodeJS.LTS -e`, `winget install --id astral-sh.uv -e`, poppler — по ссылке из `winget search poppler`.
- Проверка: те же команды отвечают версиями.

**Шаг 2. Папка студии.** Студия ставится в текущую рабочую папку сотрудника — там же, где у него уже подключена CRM. Другая папка — только если эта синхронизируется с облаком: git в такой папке ломается, обновление навыков перестаёт работать. Проверяй по факту, не по названию:
- Mac: папка внутри `~/Desktop` или `~/Documents` синхронизируется, только если есть `~/Library/Mobile Documents/com~apple~CloudDocs/Desktop` (или `…/Documents`) — это включённая в iCloud синхронизация «Рабочий стол и Документы»; папка внутри `~/Library/Mobile Documents`, `~/Library/CloudStorage`, OneDrive, Яндекс Диска, Google Диска — синхронизируется всегда. Windows: OneDrive (в том числе «Рабочий стол», если он в OneDrive), Яндекс Диск, Google Диск.
- Синхронизируется — скажи сотруднику, почему студию сюда нельзя, и предложи новую папку в домашней: `~/kontent-zavod`, а если такая уже есть и она не этого сотрудника — `~/kontent-zavod-<имя>`. Чужие папки не трогай. В новой папке CRM нужно будет подключить заново (шаг 3), а правила сотрудника из прежней папки — перенести (ниже).

Как ставить:
- Папка уже студия (в ней `CLAUDE.md` «Контент завод») — `git pull --ff-only`.
- Папка пустая или новая — `git clone https://github.com/RobertiG/kontent-zavod.git <папка>`.
- В папке есть файлы сотрудника — `git init -b main && git remote add origin https://github.com/RobertiG/kontent-zavod.git && git fetch origin main && git checkout -t origin/main`: его файлы остаются на месте и в GitHub не попадают.
- **Свои правила сотрудника** (`CLAUDE.md` в его папке — кто он, как обращаться, его границы): до установки скажи «Ваши правила сохраню под именем CLAUDE.local.md — Claude будет читать их вместе с правилами студии» и переименуй `CLAUDE.md` → `CLAUDE.local.md`; новая папка — скопируй его туда под этим именем. `CLAUDE.local.md` в GitHub не попадает. Есть свой `AGENTS.md` (Codex) — не трогай, спроси Роберта.
- Правила сотрудника запрещают то, что нужно студии (браузер для Gemini, MPStats, работу вне папки), — не обходи: перечисли сотруднику, что именно запрещено и чего из-за этого не будет, и попроси решение у Роберта.
- Проверка: в папке есть `CLAUDE.md` студии и `.claude/skills/kontent/SKILL.md`; правила сотрудника — в `CLAUDE.local.md`.

**Шаг 3. CRM в папке студии.** Проверь: `cd "<папка студии>" && claude mcp list` (Codex — часть 4). `uchet … ✓ Connected` — «CRM уже подключена в этой папке». Нет — попроси сотрудника: «Откройте CRM → «Мой аккаунт», скопируйте строку для Claude Code. Откройте программу «Терминал» (Windows — PowerShell), введите `cd "<папка студии>"`, нажмите Enter, вставьте строку и нажмите Enter». Подключение будет работать только в этой папке — так и нужно. Имя подключения — **uchet**: на него опираются навыки. Ключ в чат не просить.
- Проверка: `claude mcp list` — `uchet … ✓ Connected`; `whoami` — в шаге 8.

**Шаг 4. MPStats.** Проверь `claude mcp list`. `mpstats` уже есть — это чужое или общее подключение: спроси «На компьютере уже подключён MPStats. Использовать его или подключить ваш?» и сделай по ответу. Нет — сотрудник сам выполняет в «Терминале», в папке студии, строку от Роберта: `claude mcp add --transport http mpstats "https://mcp.mpstats.io/mcp?token=<токен>&tools=all"`. Токен в чат не вставлять. Строки нет — пропусти этап и напомни в сводке.
- Проверка: `claude mcp list` — `mpstats … ✓ Connected`.

**Шаг 5. Gemini в браузере** (Codex — часть 4). Нужен плагин Claude Code **chrome-devtools-mcp** (`/plugin` → claude-plugins-official → chrome-devtools-mcp → установить; в настройках студии он уже указан). У плагина один браузер на всю учётную запись компьютера: если в нём уже выполнен вход в чужой Google — спроси, прежде чем менять. Вход: закрыть Chrome плагина (`pkill -f chrome-devtools-mcp/chrome-profile`), запустить обычный Chrome с тем же профилем — `open -na "Google Chrome" --args --user-data-dir="$HOME/.cache/chrome-devtools-mcp/chrome-profile" --password-store=basic --use-mock-keychain` — сотрудник входит в Google и открывает gemini.google.com, затем закрыть этот Chrome (`pkill -TERM -f chrome-devtools-mcp/chrome-profile`), чтобы вход сохранился. Google не пускает в Chrome, запущенный плагином, — поэтому так.
- Проверка: плагин открывает gemini.google.com уже с входом, видна подписка Pro.

**Шаг 6. Навыки документов** (только Claude). Claude → Настройки → Возможности: включить навыки работы с PDF и Word. Нет такого пункта — скажи Роберту.

**Шаг 7. Новая сессия.** Скажи сотруднику дословно:
> Настройка почти готова. Откройте помощника заново в папке студии: Claude → Code → новая сессия → Local → Select folder → **<папка студии>**. На вопрос о доверии — «Доверять». Напишите: **«Закончи настройку по SETUP.md, шаг 8»**. Эту сессию можно закрыть.

**Шаг 8 (новая сессия в папке студии).** Шаги 0–7 уже сделаны.
- `pwd` — папка студии, не в облачной папке.
- MCP `uchet`: `whoami` — ответ с именем сотрудника и открытыми разделами (нужны `content_products` и/или `studio_*`).
- Назови сотруднику три правила из CLAUDE.md своими словами: клиенту ничего не уходит без «да» Кристины; в карточках только то, что есть в паспорте; деньги на генерации — только с согласия.
- Спроси: «Наберите / — есть ли в списке /kontent, /клиент, /заказ?».
- Пробный запуск без записи: `/kontent что готово по <любой товар, открытый сотруднику>` — опись товара. «Нет прав» — Роберту: открыть раздел «Контент по товарам» и/или студию.
- Сводка: что настроено, что пропущено и что из-за этого пока не работает.

## Часть 3. Если что-то не так

| Сообщение | Что значит | Что делать |
|---|---|---|
| `uchet` не подключён / «нет прав» | CRM подключена в другой папке, нет ключа или раздел не открыт | шаг 3 — подключить в папке студии; ключ — «Мой аккаунт» в CRM; права — Роберту |
| не видна папка товара / «нет прав» на файлы | раздел товара не открыт сотруднику в CRM | доступ — Роберту |
| Gemini просит войти | слетел вход в браузере плагина | шаг 5 |
| Gemini «лимит исчерпан» | кончился лимит подписки (~25 картинок за окно) | подождать сброса; генерировать партиями |
| «ВНИМАНИЕ: правила не обновились» | на компьютере правки, которых нет в GitHub | `git status`, показать Роберту, ничего не удалять |
| в меню «/» нет `/kontent` | открыта не та папка или ей не доверились | новая сессия в папке студии, «Доверять» |
| ошибка хука при запуске (Windows) | автообновление правил написано для bash | в `.claude/settings.local.json` записать `{"disableAllHooks": true}`; в начале дня говорить «обнови правила» |

## Часть 4. Если сотрудник работает в Codex

Первая версия от 13.11.2026: навыки те же, отличия — в `AGENTS.md`. Картинки Codex рисует встроенным инструментом по подписке ChatGPT, видеообложку — в Gemini через свой браузер; видео 15 / 30 / 60 сек пока не делаем. Встроенное рисование, браузер и подключения Codex проверяются на первых прогонах — что не сработает, скажи Роберту.

Нужно заранее: подписка ChatGPT **Plus или выше**, Codex — приложение (chatgpt.com/codex) или `npm install -g @openai/codex`, вход — «Sign in with ChatGPT»; остальное — как в части 1. Этапы и правила ведения — те же, что в части 2; отличия:

1. **Этапы 0–2** — без изменений; этап 6 не нужен.
2. **Навыки для Codex** (после этапа 2): Codex ищет навыки в `.agents/skills`, у нас они в `.claude/skills` — нужна ссылка (в GitHub не попадает). Без неё Codex не видит навыки студии.
   - Mac: `cd "<папка студии>" && mkdir -p .agents && ln -s ../.claude/skills .agents/skills`
   - Windows (PowerShell): `cd "<папка студии>"; mkdir .agents; cmd /c mklink /J .agents\skills .claude\skills`
   - Проверка: `ls .agents/skills/kontent/SKILL.md` — файл есть.
3. **CRM** (этап 3) — для папки студии, не для всего компьютера: настройка Codex этой папки (`.codex/config.toml` в ней, в GitHub не попадает). Способ — со страницы «Мой аккаунт» → «Подключить ИИ-помощника»; на странице пока только строка для Claude — подключение Codex ждёт доработки CRM, скажи Роберту. Имя подключения — **uchet**.
4. **MPStats** (этап 4) — так же, для папки студии, строкой от Роберта; токен в чат не вставлять.
5. **Gemini** (этап 5) — войти в Google в браузере Codex и открыть gemini.google.com; подписка Gemini Pro под этим аккаунтом. Чужой вход — спроси.
6. **Проверка** (этап 8) — новая сессия Codex в папке студии: `codex mcp list` показывает `uchet` и `mpstats`; сообщение «что готово по <товар, открытый сотруднику>» — опись товара из CRM.

Правила обновляются сами: по `AGENTS.md` Codex в начале сессии выполняет `git pull`.
